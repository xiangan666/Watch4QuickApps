# 排错说明

## 建议收集方式

在「日志」页开启「详细日志」，复现一次操作，点击「导出日志文件」保存 `.txt`。导出的记录保留毫秒时间、时区、应用版本与 Android API，可区分连接失败、鉴权失败、设备拒绝和传输失败。日志不包含配对密钥或完整协议载荷。

| 现象 | 已核实的原因或检查方式 | 处理 |
| --- | --- | --- |
| 已允许附近设备，仍提示权限已撤销 | Android 12 / MIUI 在 `BluetoothSocket.connect()` 仍检查旧 `BLUETOOTH` 权限；0.1.0 的 `maxSdkVersion=30` 排除了该声明 | 覆盖安装 0.1.1 或更新版本，保留系统附近设备授权 |
| Root 已允许，却无法读取配对信息 | 应用数据隔离的挂载命名空间，或系统警告混入 JSON | 当前固定 Root 操作使用 `su --mount-master`，并分别处理 stdout/stderr；已在 APatch 环境验证 |
| Shizuku 授权后无法读取数据库 | ADB / shell 模式不是 Root，不能读取运动健康私有数据 | 使用已取得 Root 的手机，或 Root 模式 Shizuku；软件不会自行提升系统权限 |
| 预检返回状态码 3 | 当前运动健康客户端将该值映射为设备存储空间已满 | 管理器保留连接；在官方界面清理自己选择的无用内容后重试。该应答本身不提供精确剩余字节数 |
| `read failed, socket might closed or timeout, read ret: -1` | 建立 RFCOMM 时套接字失败。仅凭这一行不能区分设备暂不可用、断开后的暂态或另一个客户端占用 | 看发生阶段；保持手表靠近，稍后重连。确需释放官方客户端连接时，自行勾选临时停止运动健康 |
| `Connection reset by peer` 或设备已断开 | 传输端已关闭，与安装预检拒绝不同 | 日志记录原始异常链；重新连接。管理器只在真实传输/鉴权异常时关闭失效会话 |
| RPK 列表没有目标包 | 传输或安装未确认完成 | 仅看到传输完成不代表安装完成；核对设备完成事件和刷新后的列表 |
| 没有日志导出保存器 | 系统文档组件未启用或没有处理 `ACTION_CREATE_DOCUMENT` 的应用 | 启用系统文件管理/文档组件后重试，无须给管理器广泛存储权限 |

## 已确认的安装事实

2026-11-16 的本机记录中，象棋包 `com.xiangan.watch.xiangqi`（108066 字节）先遇到预检拒绝 3，稍后预检返回 0，传输预检返回 0、分片长度 2048，完成 53 片传输并核对到安装完成。使用者随后明确确认可以安装。

状态码描述依据当前客户端的错误映射，不代表管理器已经测得设备全部分区容量。软件不会为了消除这一提示自动清空存储、解绑、刷机或删除其他内容。

## 更新与恢复

覆盖安装保持 `com.xiangan.watch4manager` 包名和相同 APK 签名，保留本机配对信息与日志。若更换签名，Android 会拒绝覆盖安装；先保留需要的日志，再决定是否卸载重装，卸载会清除管理器自己的密钥和日志。

断开管理器连接后，可在连接页打开小米运动健康，恢复官方同步。清除管理器保存的密钥不会解除手表绑定。
